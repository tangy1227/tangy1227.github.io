# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev       # Vite dev server with HMR
npm run build     # tsc -b (type-check) then vite build → dist/
npm run lint      # ESLint (flat config, eslint.config.js)
npm run preview   # serve the built dist/
npm run photos    # originals in old_resources/website_pics/ → public/photos/ (see Photos below)
npx tsc -b        # type-check only
```

There is no test suite. Playwright is a devDependency but has no config or tests. Check changes visually in a browser. Local screenshots go in `screenshot/`, which is gitignored. `README.md` is still the unmodified Vite template.

## Stack

React 19, Vite 8, TypeScript 6 and Tailwind CSS v4. Tailwind is wired in through `@tailwindcss/vite`, so there is no `tailwind.config`; all custom CSS lives in `src/index.css`. All animation uses **framer-motion**, and smooth scrolling uses **Lenis**. `gsap` and `@gsap/react` are installed but not imported anywhere. `src/App.css` and `src/assets/*` are leftovers from the template and aren't used.

The TS config sets `verbatimModuleSyntax` (type-only imports must use `import type`), `erasableSyntaxOnly` (no enums, namespaces or parameter properties) and `noUnusedLocals`/`noUnusedParameters`. ESLint uses the recommended rules from `eslint-plugin-react-hooks` v7, which flag setState called synchronously inside effects.

## Architecture

This is a single-page portfolio with no router. `src/App.tsx` stacks the sections in order: Intro curtain → Nav → Hero → Marquee band → About → Academia → Music → Photography → Contact. Navigation uses section `id`s (`#top`, `#about`, `#academia`, `#music`, `#photography`, `#contact`). The `links` array in `Nav.tsx` and its IntersectionObserver for the active link both depend on these ids, so renaming or adding a section means updating Nav as well.

### Load sequence
`Intro` shows a full-screen curtain and stops Lenis while it is up. It calls `onDone` as the curtain *starts* lifting, which sets `ready` in App. `Hero` gets `ready` and passes `show={ready}` to its reveal components, so the hero animation overlaps the curtain exit instead of waiting on in-view detection. When the user prefers reduced motion, Intro skips straight to `done`.

### Scroll layering (sticky hero)
`Hero` is `sticky top-0 z-0 h-svh`. **Every later section must use the `.section` class** (`position: relative; z-index: 10; background: var(--bg)`) so it slides over the pinned hero. A section without it, or with a transparent background, will show the hero through it. Hero's scale, opacity and parallax are framer-motion `useTransform`s on `scrollY`, scaled by the hero's own height (a ResizeObserver), not `window.innerHeight`, which changes on phones whenever the browser toolbar shows or hides. Its vertical fit depends on `.hero-title` / `.hero-strip` in `index.css`: the headline font is clamped against both `vw` and `vh`, the photo strip is hidden below 820px viewport height, `.hero`/`.hero-eyebrow` tighten below 520px (landscape phones) and `.hero-sub` is hidden below 480px. The text block is centred with `my-auto` so it pins to the top rather than being cut off when it doesn't fit. `html, body` use `overflow-x: clip`, not `hidden`: `hidden` would make body a scroll container and break every `position: sticky`.

### Lenis
`components/SmoothScroll.tsx` owns the one Lenis instance. It sets `history.scrollRestoration = 'manual'` and scrolls to the top so the intro always plays. `src/lib/lenis.ts` is a small `useSyncExternalStore` store, and any component reads the instance with `useLenis()` (no context provider). Lenis still fires native scroll events, so framer-motion's `useScroll`/`useInView` work unchanged. Code that locks scrolling calls `lenis.stop()` and must restore it in effect cleanup. `lenis.stop()` sets `overflow: clip` on `<html>`, which drops the scrollbar and reflows the page, so overlays (the photo viewer, the theme reveal) use `holdScroll()` from `src/lib/lenis.ts` instead. It stops the glide in place, swallows wheel/touch input, is ref-counted, and returns a release function. The Nav mobile menu only ever *stops* Lenis while open, so it never overrides the Intro's lock. It closes on Escape and when the viewport grows past `md` (a rotated tablet), since above `md` it is hidden but would otherwise keep the page locked. Programmatic navigation uses `lenis.scrollTo(href, …)`; plain anchor links are smoothed by Lenis's `anchors` option. The smoothing follows the input device: Lenis's `virtualScroll` hook sets `lenis.options.lerp` per wheel event to `TRACKPAD_LERP` (trackpads already glide, so heavy smoothing reads as lag) or `WHEEL_LERP`. Tune those two constants at the top of `SmoothScroll.tsx`. Elements that scroll on their own inside the page need `data-lenis-prevent` (the mobile menu) or `data-lenis-prevent-horizontal` (the Archive swipe row).

### Music archive timeline
`Archive` in `Music.tsx` renders one of two modes from the same pieces (`ArchiveIntro`, `YearCard`, `YearNav`):
- `PinnedTimeline` when `PINNED_QUERY` matches (≥768px wide, ≥600px tall, mouse/trackpad) and motion isn't reduced. The intro is the first panel of a row that slides sideways while the frame is pinned. The outer div is `100svh + distance * SCROLL_LENGTH / (1 - 2 * HOLD)` tall, where `distance` is the row's `scrollWidth` minus the frame width, re-measured by a ResizeObserver (window resize, fonts loading). Scroll maps linearly to `x`, held still for `HOLD` at each end. `SCROLL_LENGTH` sets the speed (1 = in step with the scroll). The frame is `overflow-clip`, not `hidden`, so keyboard focus can't scroll it out of sync; focusing a link jumps the page to its year instead.
- `SwipeTimeline` otherwise (touch, small screens, reduced motion): a native horizontal scroller with snap points.
The year in focus is filled and the rest are outlined (`.year-num` / `.is-dim` in `index.css`). `YearNav`'s buttons jump to a year in either mode.

### Motion system
- `src/lib/motion.ts` holds the shared bezier curves (`EASE_OUT_EXPO`, `EASE_OUT`, `EASE_IN_OUT_SOFT`, `EASE_IN_OUT`) and staggers. In CSS, `--ease-expo` mirrors `EASE_OUT_EXPO`. Use these rather than inline curves. The motion language copies the OFF+BRAND style used on landonorris.com.
- `src/components/motion/` holds the reusable primitives. `RevealLines`, `RevealChars` and `RevealImage` follow one pattern: an optional `show` prop gives external control, and without it they reveal once on `useInView`. `RevealChars` swaps to plain text once its last character lands, so labels can wrap and copy cleanly. `RevealImage` clips its zoomed content, which would otherwise widen the page on phones. `RevealLines` and `RevealImage` wipe a solid "highlighter" bar off the content. On a non-default background, pass a matching `bar` color, e.g. `bar="var(--bg-alt)"` in the Photography section.
- `RollText` is pure CSS. It animates when a `.group` ancestor (or the element itself with `roll-hover`) is hovered, so wrap it in an element with `group`. `ArrowSwap` (in `ui/Button.tsx`) works the same way.
- Hover-only CSS effects (roll text, button fills, arrows, photo colour, cards, marquee pause) sit inside `@media (hover: hover)` so a tap on a touch screen doesn't leave them stuck; Tailwind's `hover:` variants already do this. Under `(hover: none)` photos are shown in colour. `src/lib/media.ts` has `useMediaQuery(query)` (a `useSyncExternalStore` store like `lenis.ts` and `theme.ts`) and `FINE_POINTER` for components that need the same split in JS.
- Every animated component checks `useReducedMotion()` and renders plain static markup when it is set. `index.css` also has a `prefers-reduced-motion` block for the CSS animations. New animations should keep both paths.

### Styling conventions
Design tokens live as CSS variables on `:root` in `index.css` (light values: `--bg #fafaf8`, `--bg-alt #f0efea`, `--ink #0a0a0a`, `--ink-soft`, `--muted #6b6b66`, `--faint`, `--line #e3e2dc`, `--line-strong`, `--accent #ffb800`, `--on-accent`, plus photo/media/shadow tokens). An `@theme inline` block registers them as Tailwind colours, so components write `bg-bg`, `bg-bg-alt`, `text-ink`, `text-muted`, `border-line`, `bg-accent`, `text-on-accent` (opacity modifiers work: `bg-bg/85`). **Never hardcode hex values in components**, because they won't follow the theme. Text or icons on the accent use `--on-accent`, which stays dark in both themes, never `--ink`. The only fixed colours are the always-dark surfaces, the `Intro` curtain and the mobile menu (`#0a0a0a` / `#fafaf8`). `.section` is unlayered CSS, so its `background: var(--bg)` beats Tailwind's layered `bg-*` utilities. For the alternate tone use `.section-alt` (Academia, Photography), not `bg-bg-alt`; tags inside it switch to `--bg`. Section headlines use `.display .section-title` (one fluid size). Section eyebrows are numbered with `ui/SectionLabel` (01 About … 05 Contact), matching the mobile menu's order. Shared classes are defined in `index.css` rather than as components: `.display` (big uppercase headline), `.eyebrow` (small-caps label with an accent dash), `.btn`/`.btn-outline`, `.tag`, `.photo` (placeholder tile, grayscale until hover) and `.media`. Fonts are Inter for body text and Space Grotesk for `.font-display`/`.display`, both loaded by the Google Fonts `<link>` (with preconnect) in `index.html`.

### Theme (light / dark)
`:root[data-theme='dark']` in `index.css` overrides the tokens with a warm-charcoal palette (`--bg #121211`, `--ink #f2f1ec`; `--muted`/`--faint` swap values; the accent is unchanged). The page bg is lifted off `#0a0a0a` on purpose, so the intro curtain still reads as its own plane. The user's preference (`system` | `light` | `dark`) is stored in `localStorage['theme']`, and a missing key means `system`. An inline script in `index.html` resolves it and sets `data-theme` before first paint. `src/lib/theme.ts` repeats that logic, so keep the two in sync. Both also set `<meta name="theme-color">` (the mobile browser bar) to the page background. It is a `useSyncExternalStore` store (`useThemePreference()`, `setThemePreference(pref, origin)`) that follows live OS changes in system mode and syncs across tabs. Switching reveals the new theme as a View Transition circle from the clicked button, with an instant swap under reduced motion or without the API. The circle is a CSS animation on `::view-transition-new(root)`, scoped to `html.theme-reveal` and driven by `--reveal-x/y/r`. Don't start it with `animate()` from `transition.ready`: that can land a frame late and flash the whole new theme. During the reveal, scrolling is held with `holdScroll()`, because the old theme is a still snapshot and any scroll tears it from the live page. CSS transitions are suppressed for the frame where the tokens flip (`.theme-switching`). `components/ThemeToggle.tsx` is the 3-way control in the nav, styled with `currentColor` so it also works on the dark mobile menu.

### Photos
The original photos live in `old_resources/website_pics/` (gitignored, about 180MB). Never put originals in `public/`, because everything there ships in the build. `npm run photos` (`scripts/process-photos.mjs`) runs headless Chromium to write `public/photos/<slug>-1200.jpg` and `-2048.jpg`, converting to sRGB and stripping all metadata, including GPS. It also regenerates `src/data/photos.generated.ts` with each photo's size. The slug is the file name, lower-cased and hyphenated. `src/data/photos.ts` holds the captions and the gallery's row layout (`galleryRows`) and is shared by the hero strip, the gallery, `PhotoViewer` and the About portrait. Gallery rows are justified: each tile's `flex-grow` and `aspect-ratio` equal its width/height, so a row fills the width at one height with nothing cropped. Below `md`, a row's first photo goes full width. `PhotoViewer` is portaled to `<body>`, because inside `.section` (z-10) it would render under the nav.

### Content
- Each section keeps its content as const arrays at the top of its component file, e.g. `projects` in Academia; `releases`, `archive` and `tools` in Music; `photos` in Photography; `skillGroups` in About.
- All external URLs and the email address live in `src/data/links.ts` (`links`, `socials`). Import from there instead of hardcoding URLs.
- `links.ts` also has `repo(name)` and `youtubeVideo(id)` helpers. Academia's `featured` cards take `media` (`youtube`, or `figure` for an image in `public/projects/`), and `more` lists compact rows. The Music archive's tracks link to YouTube when they have a `youtube` id.
- Empty values hide UI instead of rendering dead links: `links.cv` (Download CV) and tool links with `href: ''`. What's still missing is marked `TODO`: the CV, the drum-transcription year and links, the Max patch links, and the "Duncan + Yilong" video.
- `.media` is unlayered CSS like `.section`, so Tailwind utilities can't override it. Use the `.media-static` / `.figure` classes for non-clickable frames.
- `MediaEmbed` is a click-to-load facade, so no iframe loads until the user clicks. For YouTube it builds the thumbnail from the video id; SoundCloud takes a full URL.
- `old_resources/` is gitignored. It holds the source material for the site copy: `aboutme.txt`, the old hobby-site URLs and screenshots.
